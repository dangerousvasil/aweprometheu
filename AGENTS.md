# AGENTS.md

Инструкции для ИИ-агентов, работающих с этим репозиторием. Описание библиотеки для конечного пользователя — в [README.md](README.md).

## Что это за проект

Go-библиотека `github.com/dangerousvasil/aweprometheu` — обёртка над `prometheus/client_golang`: глобальный stats-сервер (`/metrics`, `/probes/ready`, `/probes/live`), пакетные хелперы записи метрик с позиционными лейблами, обработка OS-сигналов через `InitCTX`. Демо-приложение — в `internal/cmd`.

## Команды

- Тесты: `go test ./...`
- Демо: `go run ./internal/cmd` (порт — `DEMO_PORT`, по умолчанию 9099)
- Форматирование: `gofmt -l .` — не должно ничего выводить
- Статический анализ: `go vet ./...`

Go 1.27. Внешние зависимости: `prometheus/client_golang`, `golang.org/x/exp`.

## Структура

- `prometheus.go` — `NewHandler` регистрирует семейства метрик в default-реестре; хелперы `Counter`, `CounterAdd`, `Error`, `Gauge`, `Histogram`, `Summary`, `SetSqlMetrics`.
- `stats.go` — глобальный stats-сервер: `New` (один порт), `NewOnPorts` (плюс отдельные порты проб live/ready), `Stats` (внешние `*atomic.Bool` на обе пробы); пробы `/probes/ready`, `/probes/live` и команды `Ok`/`Fail` (обе сразу), `OkLive`/`FailLive`, `OkReady`/`FailReady`.
- `signal.go` — `InitCTX` (SIGHUP/SIGINT/SIGTERM/SIGQUIT → `IsStop.Store(true)`, отмена контекста).
- `logger.go` — настраиваемый логгер библиотеки: `SetLogger`, хелпер `lg()` (по умолчанию `slog.Default()`).
- `internal/cmd/main.go` — runnable-пример: сервер + синтетическая нагрузка.
- `stats_test.go` — все тесты, включая парсер text-экспозиции.

## Инварианты, которые нельзя ломать

- **Один stats-сервер на процесс.** `instance` в `stats.go` глобальный; повторный `New`/`Stats` игнорируется с warning. Семейства регистрируются через `promauto` в default-реестре — повторная регистрация паникует. Поэтому тесты обязаны работать с единственным инстансом, поднятым `TestMiniAppUnderLoad`, и не могут поднимать свои серверы.
- **Имена семейств строятся из имени приложения.** `New("demo-app", ...)` даёт в text-экспозиции `demo_app_counter_metrics`: недопустимые в legacy-именах символы (дефис) экранируются в подчёркивание, значения лейблов не экранируются. Это ожидаемое поведение, тесты его проверяют — не «чините» такие имена.
- **Хелперы до старта сервера — no-op.** Если `New`/`Stats` не вызваны, `Counter`/`Gauge`/`Histogram`/`Summary`/`SetSqlMetrics`/`Error` пишут только `slog.Debug` и не паникуют. Сохранять.
- **Команды проб паникуют до старта сервера** — `Ok`/`Fail`/`OkLive`/`FailLive`/`OkReady`/`FailReady` разыменовывают nil `instance`. Вызывайте их только после `New`/`NewOnPorts`/`Stats`.
- **Отдельные порты проб отвечают на любой путь** (`statusBoolCheckHandler` без привязки к маршруту) — путь пробы задаётся конфигурацией мониторинга. Не добавляйте привязку к конкретному пути.
- **`IsStop` — `atomic.Bool`** (чтение через `Load`): обработчик сигнала делает `Store(true)` до отмены контекста, поэтому после `<-ctx.Done()` значение гарантированно `true`. Не возвращать к plain bool — с ним была data race между обработчиком сигнала и читателями (`go test -race`).

## Соглашения

- Комментарии и документация — на русском языке.
- Лейблы `app`/`seg` подставляются автоматически из аргументов старта; пользовательские метки позиционные `A..D`; `Error` жёстко занимает `A`, метки пользователя начинаются с `B`.
- Логирование — везде stdlib `log/slog` (зависимость `golang.org/x/exp` удалена). Библиотека пишет через `lg()` — логгер, заданный `SetLogger`, по умолчанию `slog.Default()`.

## Особенности тестов

- `TestInitCTX` отправляет настоящую SIGINT процессу тестового бинарника (`syscall.Kill(Getpid(), SIGINT)`) — никогда не помечайте его и его подтесты `t.Parallel()`.
- `testPort` — порт инстанса, поднятого `TestMiniAppUnderLoad`; `TestInitCTX` переиспользует его для скрейпа `/metrics`. При отдельном запуске (`-run TestInitCTX`) скрейп пропускается.
- Подтесты выполняются последовательно против одного инстанса — порядок подтестов в `TestMiniAppUnderLoad` важен.
- Повторный старт проверяется в том числе негативно: порты «игнорированного» `NewOnPorts` должны оставаться незанятыми (хелпер `refused`).
- Сьют не поддерживает `-count > 1`: глобальный синглтон не даёт повторно стартовать stats-сервер в том же процессе, тесты второго прохода падают на `waitHTTP`/`IsStop`. Штатная проверка — `go test ./...` одним проходом.
